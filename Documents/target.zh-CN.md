# Target

> [English Version](./target.md)

## 当前产品目标

将 ZFS Manager 打造成适合单机或小型实验室环境的 ZFS Web 管理界面，让运维人员无需频繁切换到命令行，也能完成常见的存储池、数据集、任务和计划任务管理工作流。

## 已交付能力

### 存储池工作流

- 存储池状态、容量和健康概览
- 拓扑可视化
- 可编辑的池属性
- 支持添加 `log`、`cache`、`special`、`dedup` 和 `spare` 设备
- 创建新池
  - pool 属性
  - 根数据集属性
  - 分步骤规划数据 vdev 和辅助 vdev
- 销毁存储池
- 移除受支持的拓扑目标
- `scrub` 启动与停止
- 在池详情中展示当前 `scan` / `scrub` 状态、进度和 ETA

### 数据集工作流

- dataset 和 zvol 清单
- 可展开的数据集树
- 可选快照显示
- 创建数据集和 zvol 子项
- 编辑数据集属性
- 销毁数据集和 zvol

### 任务与计划任务工作流

- 独立的任务记录页，用于查看近期写操作和长任务
- 面向 pool 和 dataset 写请求的统一任务模型
- 任务详情展示状态、进度、阶段、时间戳和命令日志
- 基于 `SQLite` 的任务持久化
- 最近未完成任务的启动恢复
- 基于 `zpool status` 的 `scrub` 进度恢复
- 独立的计划任务页面
- 支持按周配置定时 `scrub`，并可启用、停用、删除
- 为后续定时快照预留了占位区域
- 任务记录已支持分页、每页条数控制和按状态筛选

### UI 能力

- 中英文切换
- 基于浏览器语言的初始语言检测
- 在前端持久化语言偏好
- 已翻译的导航、仪表盘、存储池、数据集、计划任务、任务记录、设置和对话框文案

## 前端方向

- `PoolsView` 和 `DatasetsView` 继续作为页面容器
- `TasksView` 作为任务记录、长任务和命令日志的统一可视层
- `SchedulesView` 负责定时工作流定义，例如定时 `scrub`
- `PoolsView` 中的池详情继续承载 `scrub` 入口和实时状态摘要
- 共享的属性编辑器、对话框、命令结果视图和工具面板继续集中在 `frontend/src/components/common/`
- 所有用户可见文本继续通过 i18n key 提供

## 后端方向

- 写操作继续统一登记为运维可见任务
- 任务系统当前采用“内存运行态 + SQLite 持久化”的组合
- 启动顺序为：
  1. 加载持久化任务历史
  2. 刷新远端状态
  3. 对未完成任务做状态对账
  4. 启动后台轮询与调度器
- `scrub` 已经成为第一个完整接入恢复体系的长任务样板
- 定时工作流已经接入同一套任务基础设施，而不是绕过任务系统
- 后续 `replace`、`resilver`、`expansion` 和定时快照应复用同一套恢复模型

## 后续步骤

- 将活动任务对账进一步并入后台轮询，而不只是在读取任务接口时触发
- 增加更多 pool 级长任务恢复器，优先从 `replace/resilver` 开始
- 在计划任务页面上继续补齐定时快照与保留策略
- 继续补充任务事件、日志和运维审计上下文
- 持续扩展新工作流的 i18n 文案与状态提示
