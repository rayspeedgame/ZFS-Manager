# Target

> [English Version](./target.md)

## 当前产品目标

将 ZFS Manager 打造成适合单机或小型实验室环境的 ZFS Web 管理界面，让运维人员无需频繁切换到命令行，也能完成常见的存储池、数据集和长任务管理工作流。

## 已完成功能

### 存储池工作流

- 存储池状态、容量和健康概览
- 拓扑可视化
- 可编辑的池属性
- 支持添加 `log`、`cache`、`special`、`dedup` 和 `spare` 设备
- 创建新池
  - pool 属性
  - 根数据集属性
  - 分步骤规划数据 vdev 和辅助 vdev
- 销毁存储池
- 移除受支持的拓扑目标
- `scrub` 启动与停止按钮
- 在池详情中展示当前 `scan` / `scrub` 状态、进度和 ETA

### 数据集工作流

- dataset 和 zvol 清单
- 可展开的数据集树
- 可选快照显示
- 创建数据集和 zvol 子项
- 编辑数据集属性
- 销毁数据集和 zvol

### 任务工作流

- 独立的任务页，用于查看最近写操作
- 面向 pool 和 dataset 写请求的统一任务模型
- 展示任务状态、进度、阶段、时间戳和命令日志
- 任务记录已通过 `SQLite` 持久化
- 后端重启后会重新加载最近任务历史
- 启动恢复流程已经接入
  - 对当前已支持的短任务做状态对账
  - 对 `scrub` 做基于 `zpool status` 的进度恢复
- 任务查询接口在读取时会对活动任务做一次状态对账

### UI 功能

- 中英文切换
- 基于浏览器语言的初始语言检测
- 在前端持久化语言偏好
- 已翻译的导航、仪表盘、存储池、数据集、任务、设置和对话框文案

## 前端方向

- `PoolsView` 和 `DatasetsView` 继续作为页面容器
- `TasksView` 作为最近写操作、长任务和命令日志的统一可视层
- `PoolsView` 中的池详情现在承载 `scrub` 操作入口和状态摘要
- 共享的属性编辑器、对话框、命令结果和日志组件继续集中在 `frontend/src/components/common/`
- 所有用户可见文本继续通过 i18n key 提供

## 后端方向

- 写操作继续统一登记为运维可见任务
- 任务系统当前采用“内存运行态 + SQLite 持久化”的组合
- 启动时先加载任务，再刷新远端状态，再执行任务恢复
- `scrub` 已成为第一个接入恢复层的长任务样板
- 后续 `replace`、`resilver`、`expansion` 和定时任务应复用同一套恢复机制

## 后续步骤

- 将活动任务对账进一步并入后台轮询，而不只是在任务接口读取时触发
- 增加 `scrub` 历史和定时 `scrub`
- 增加更多池级长任务恢复器，例如 `replace/resilver`
- 继续补充快照、调度任务和审计日志
- 继续扩展前端文案与状态提示覆盖
